## 1. 总体判断

**这是一个功能较完整、具有明确视觉定位和较强测试意识的本地优先韩语学习应用，可以支撑个人学习试用；但数据导入保护、教学内容准确性和移动端任务效率仍有需要优先处理的问题。**

项目的主要矛盾不是缺少页面，而是已有的课程、词库、复习、听读、输出和路线系统已经相当丰富，界面组织和状态契约尚未完全跟上复杂度。继续直接扩充课程与功能，会放大维护、验证和认知成本。

自动化检查全部通过，不等于没有缺陷。本次发现的错误备份接收、首课字母拆解错误、标题行内排版、移动端无名称按钮，都能与“387 项单测通过”同时存在。

### 3.2 技术组织

Next.js 16.2.12 + React 19.2.1 + TypeScript + Tailwind。页面使用 App Router，大多数交互页面为 Client Component，课程通过 `generateStaticParams()` 预生成。

数据流可以概括为：课程/词库静态数据 → 页面与统一 DrillRunner → learning 模块提交 → localStorage/IndexedDB → 事件通知 → workspace 汇总 → 推荐与进度显示。

值得保留的设计：

1. 测验引擎、SRS、草稿、录音与课程会话有独立模块。
2. 不同学习入口汇总到同一套 workspace 模型，降低统计分叉。
3. 错题使用统一 ID，若干清理操作会删除关联卡片。
4. 语音统一入口支持本地 MP3、系统语音和播放失败事件。
5. `useSyncExternalStore` 连接本地持久化状态；写入失败会通知界面。
6. 多处已有失败回滚、重复保存保护、录音失效后撤销证据的测试。

### A01 · 第一课的韩文字块拆解错误

**位置：** `src/data/lessons/depth.js:17`。

实际第一课“先数块再拆字母”显示：`看见 한글 先数两块，再拆 ㅎㅏㄴ / ㄱㅡㄱ`。其中 `글` 应为 `ㄱ + ㅡ + ㄹ`，结尾写成 `ㄱ` 会组成 `극`。这是教学内容错误，不是显示字体造成的误读。

**影响：** 第一课就是零基础学习者建立字块概念的地方，示例错误会直接形成错误记忆，同时损害对其他课程内容的信任。

**建议：** 修正为 `ㅎㅏㄴ / ㄱㅡㄹ`。对所有“音节 → jamo 拆解”示例增加由分解函数驱动的一致性校验；不要只针对这一个字符串写测试。对讲解文案、答案、示例和语音文本进行交叉抽查。

**验收：** 页面展示、拆解结果和实际音节一致；课程资产与内容校验通过。

### A02 · 错误结构的备份会变成空进度

**位置：** `src/lib/learning/backup.ts:65`、`:114`、`:125`。

`strictEntries` 主要检查未知 key 和 JSON 能否解析。`isValidStoredEntry()` 接受任何合法 JSON；`normalizeLearningProgress()` 则把不是记录对象的值降级为空对象。

定向调用 `parseLearningBackupText()` 已验证：当 `kirina.progress.v2` 的内容为字符串化的 `null`、`42`、`"unexpected"`、`[]` 时，返回非空备份对象，其中 `completedLessons` 为 `[]`。外层版本和 app 名称正确即可通过这一检查。

**影响：** 损坏或格式不匹配的备份可能显示“导入成功”，但用户的有效进度被空进度替换。归一化适合修复本地旧数据，不应替代破坏性导入前的结构校验。

**建议：** 在导入边界建立独立 schema：验证每个条目的对象结构、数组/记录类型和版本；将可迁移旧版本与明显错误数据区分。拒绝错误时提供具体字段原因；不执行任何写入。

**验收：** 上述四种输入必须拒绝，原进度和录音不变；合法空备份与合法旧版本有明确语义。

### A03 · 导入缺少覆盖与录音清理预览

**位置：** `src/components/layout/learning-data-panel.tsx:88`；`src/lib/learning/backup.ts:52`、`:90`、`:100`。

选择文件后，界面直接解析并调用 `restoreLearningBackup()`。恢复会替换全部受管理 key，备份中没有的 key 会被移除；随后清理全部学习录音。当前提示只说“录音不会导出，换设备后需要重新录制”，没有解释在当前设备导入也会清理已有录音。

**影响：** 导入一份旧备份、部分备份甚至在同一设备恢复刚导出的备份，都可能丢失当前录音。该流程没有用户可用的撤销。代码存在失败回滚，但它不能恢复一次“成功却出乎用户预期”的覆盖。

**建议：** 文件选中后先展示备份日期、课程/卡片/作品数量、将覆盖的数据和将清理的录音。最终按钮明确为“替换本机数据”；提供导出当前数据与单独下载录音的入口。不要在仅选中文件时立即完成覆盖。

**验收：** 取消预览不修改任何存储；最终操作前能看清录音影响；无录音迁移能力时，不暗示“完整备份”。

### A04 · 有 Audio API 但播放失败时，入门可能卡住

**位置：** `src/lib/speech.js:30`、`:120`；`src/components/learning/onboarding-flow.tsx:39`、`:184`。

`canPlayBundledSpeech()` 仅判断 `window.Audio` 是否存在；满足即返回全局语音状态 `ready`。入门页只有收到 `onstart` 才允许继续，跳过只在状态为 `missing/unsupported` 时开放，试听按钮没有处理自身 `onerror`。

**触发条件：** 浏览器存在 Audio API，但 MP3 请求失败、资源不能解码或播放发生硬错误，没有触发 `onstart`。此时全局状态仍可能为 ready，既不能继续，也不能使用“暂时没声音”的分支。

**建议：** 为试听维护 `idle/loading/playing/failed` 状态，显示重试、失败原因和明确的暂缓音频检查入口；暂缓不应伪造听力证据。音频能力可用与本次音频播放成功应分别建模。

**验收：** 在 MP3 404、媒体解码失败、浏览器拒绝播放场景下，有明确恢复路径。当前审计根据代码确认缺少分支，未执行实际故障注入。

### A05 · 标题因旧样式兼容规则失去块级排版

**位置：** `src/app/globals.css:542`；`src/app/learn/[lessonId]/lesson-client.tsx:149`。

`.inkline { display: inline; }` 应用于课程 H1。1440px 实际页面中，返回路径、课时信息和大标题从同一行开始，标题换行后回到左边界，形成明显错位。浏览器计算样式确认 H1 的 `display` 为 `inline`，蓝夜主题也同样存在。

**影响：** 页面身份和返回操作层级混乱，`mt-2`、`max-w-4xl` 不再按预期约束普通块布局；问题可能影响其他复用 `.inkline` 的标题。

**建议：** 让标题回到 block，装饰效果放在内部 span 或伪元素；课时信息与返回按钮独立排布。检查 `.eyebrow` 的行内展示是否也被用于需要独占一行的位置。

**验收：** 320/390/1024/1440 宽度下，长短课程标题均独立成行，返回按钮位置稳定。

### A06 · 窄屏数据菜单只有图标，没有可访问名称

**位置：** `src/components/layout/learning-data-panel.tsx` 的 `<summary>` 与 `hidden sm:inline` 文本。

文字“学习数据”在窄屏隐藏，图标又是 `aria-hidden`，summary 本身没有 `aria-label`。390px 浏览器可访问性树显示该按钮只有 collapsed 状态，没有名称。外层容器的“本地学习数据”标签不能替代控件自身的名称。

**建议：** 为 summary 提供稳定的 `aria-label="学习数据"`，或使用始终可读的屏幕阅读器文本。

**验收：** 桌面与移动端 AX 树均能读出“学习数据，折叠/展开”。

### A07 · 主题控件违反项目自己的 44px 触控约定

**位置：** `src/app/globals.css:429`、`:875`；`design/art-direction.md` 第 7 节。

桌面主题按钮为 26×30px，移动端进一步缩为 23×30px。390px 实测与源码一致，四个相邻按钮间距也较紧。

**影响：** 手指切换容易点错，对运动控制能力较弱的使用者尤其不便。这里依据项目自身“点击目标至少 44px”的规范，不把这一次测量直接等同于完整无障碍标准认证结论。

**建议：** 保持 12px 色点视觉尺寸，但扩展可点击区域；窄屏可改为一个 44px 的主题选择入口。

### A08 · 视觉前言占据了移动端任务空间

**位置：** `src/app/vocabulary/page.tsx:100` 附近；`src/app/immersion/page.tsx:433`、`:474`。

390×844 的首次访问状态下，词库搜索框位于文档约 1509px 处。它之前有标题、入门提示、大型模块介绍、16 个场景计数和场景图。听读页面在该状态下，当前材料标题位于约 5753px，逐句听读标题约 6993px；29 个材料按顺序出现在当前内容之前。

听读已解锁时存在“开始听读”的跳转按钮，这是有效缓解，但不能替代材料切换后的清楚落点，也不能让全部目录都保持展开成为默认移动布局。

**建议：** 词库将搜索、筛选和首批结果置于前面，场景图与规模说明收起。听读移动端把当前材料与操作放在前面，材料目录改为折叠选择器或独立面板；切换材料后管理焦点。首页可以保留较大情绪场景，工具页使用更短的介绍。

**验收：** 390px 下搜索在前一至两屏内可达；当前听读有直接操作入口，目录不再把工作区推后数千像素。以首次可操作时间和完成任务的滚动次数评价，而不只检查没有横向溢出。

### A09 · “展开全部”将词库一次性渲染为超长页面

**位置：** `src/app/vocabulary/page.tsx:53`；类似策略见语法页。

`showAll || focusedFilterActive` 时直接渲染整个筛选结果。实际点击“展开全部词汇”后，页面包含 722 个播放按钮，约 18,319 个 DOM 元素，高度约 272,411px（开发浏览器、390px 视口）。

**影响：** 低端设备的渲染、布局、输入响应和读屏遍历都存在压力；用户也难以在长页面中找回位置。这些测量证明渲染规模过大，但本次未测得特定毫秒数的卡顿。

**建议：** 首选分批加载或分页，并保留筛选条件与结果位置；真正需要连续大列表时再采用虚拟化。激活筛选也应遵守数量上限，不能绕过分批策略。

**验收：** 页面常驻词条数量有明确上限；宽泛搜索或展开操作不会一次挂载几百个复杂词条。

### A10 · 跨标签更新使复习队列陈旧后，界面缺乏恢复动作

**位置：** `src/app/review/page.tsx:64`；`src/lib/learning/workspace.ts:1270`。

为了稳定当前会话，复习页面在已有题目时忽略学习和 storage 事件。提交层又要求卡片快照与最新存储完全一致。另一标签页先复习、删除或更新该卡片后，本页仍显示旧卡，提交会返回 false，但提示为“请释放浏览器空间”，没有重新加载队列的按钮。

**影响：** 防止重复计分的保护本身是正确的，但用户看到的是错误原因和无法继续的旧题。刷新页面可以恢复，却没有被明确提供。

**建议：** 提交返回结构化结果，区分卡片不存在、已处理、快照过期和存储失败。对过期卡提示“其他页面已更新”，允许保留已完成题目并重新读取队列。

**验收：** 双标签对同一卡片操作时不会重复计分，陈旧标签有可见恢复动作。本项已完成控制流核对，尚未进行双标签浏览器端到端故障复现。

### A11 · 领域模型和页面规模增加了维护及客户端成本

**位置：** `workspace.ts` 2985 行；课程客户端 1679 行；自然表达页 1011 行；听读页 975 行；`tsconfig.json`。

workspace 同时处理 hooks、进度归一化、推荐、等级、课程、复习、作品、写入回滚和证据撤销。Client 模块静态导入课程、词库、语法等整套数据。当前 `strict: false`，允许 JS，并有较多 `any`，使接口漂移较难在编译期发现。

本次最大生产 JS chunk 为 752,441 字节，本地 gzip 估算为 252,588 字节。该数字是单个构建文件，不是首页全部下载量。图片目录约 48.84 MB，音频目录约 17.02 MB，是磁盘总量，不代表一次页面访问会全部加载。

**建议：**

1. 将进度归一化、推荐、证据、持久化提交和 React hooks 拆为有明确输入输出的模块。
2. 将课程、听读、录音等 UI 按状态所有权拆分，而不是只把 JSX 切到更多文件。
3. 为 Lesson、Drill、Material 等共享契约建立类型和数据验证，逐模块收紧空值和隐式 any。
4. 分离用于首页推荐的轻量索引与完整课程正文，评估按路由加载。
5. 用生产浏览器测量页面 JS、长任务和交互延迟后再决定动态加载边界。

不要仅按行数把文件机械拆散，也不要为拆分引入新的状态源。

### A12 · 已有强测试没有全部进入 CI，且缺少视觉/可达性断言

**位置：** `.github/workflows/ci.yml`；`scripts/smoke-browser.mjs`；`tests/korean-ui-lifecycle.test.mjs`。

CI 执行依赖审计、内容验证、Lint、类型、单测和 build，截止于 build，没有运行已有的 `check:smoke`。部分 UI 测试采用模拟组件运行时或源码字符串断言，能够约束调用关系，但不能发现真实排版与可访问名称问题。

**建议：** 在 CI 安装对应浏览器并执行生产 smoke；设置合理超时，失败时上传截图与日志。额外建立少量高价值视觉和语义检查：课程长标题、移动数据菜单名称、主题触控范围、听读当前材料落点、错误备份无写入。

**验收：** PR 中上述缺陷至少有相应保护；浏览器 smoke 失败能够阻断合入。文档中的“341 项单测”应更新为当前事实或去掉易失真的固定数字。

### A13 · 页面 metadata 尚未形成页面级内容体系

**位置：** `src/app/layout.tsx:19`；`src/app/learn/[lessonId]/page.tsx`。

当前仅根布局导出 metadata，浏览器中的课程、词库等页面使用同一全站标题。课程页没有 `generateMetadata()`；源码未见 canonical、sitemap 或 robots 入口。本次未配置站点 URL 的构建中，分享图片 URL 指向 `http://localhost:3000`。

**影响：** 多标签识别、历史记录、课程分享和公开搜索呈现不足。localhost 是当前本地配置的结果，不能据此认定线上部署也配置错误。

**建议：** 为公开内容页设置独立标题和描述；课程根据 ID 生成 metadata。部署验证要求真实站点 URL；按是否需要公开索引决定 canonical、sitemap、robots 与个人记录页策略。

### A14 · 状态文案与真实限制存在不一致

**位置：** `lesson-bridge.ts:84`；`settings/page.tsx` 的语音说明；`mastery-gate.tsx`；`drill-runner.tsx`。

具体实例：

- 未完成入门的第一课同时出现“先完成三分钟入门”和桥接卡“前置要求已满足，可以开始本课”。课程前置与入门前置用了不同口径。
- 设置页说“所有听力练习都用这里选定的语音朗读”，实际优先走统一 MP3，voiceURI 只影响系统语音路径。
- 掌握小测及跳过结果把播放失败解释为“没有韩语语音/安装系统语音”，但真实失败可能来自 MP3 请求或媒体播放。
- 部分筛选结果仍显示 `results`，与中文工具界面不一致。

**建议：** 从共享状态模型输出具体原因，而不是让页面猜失败原因。使用“可预览”“可计入进度”“音频能力可用”“本次播放失败”等准确标签；对统一录音和系统备用语音分别说明。

## 5. 视觉与交互的综合分析

### 5.1 应保留的设计资产

四季片场有明显辨识度：低饱和生活场景、统一的窗格品牌、衬线韩文和大标题、明暗主题共用结构。首页首要按钮明确；蓝夜主题仍有层次，没有变成纯黑背景。共享 `PageHeader`、`ModuleHero`、`Surface`、`VisualPanel` 和 `Button` 为后续一致性提供了基础。

照片的内容与学习语境相容，资产有来源登记和失败回退。页面通常有标题、说明、空状态与下一步，优于只呈现数据列表。

### 5.2 需要收敛的设计系统

旧纸本类名、`font-brush`、`paper-*`、`rounded-none` 等仍大量存在。仅凭名称不能认定旧设计仍在显示：项目确实提供了兼容层并隐藏了部分装饰。但通过全局选择器重写工具类语义，例如让 `rounded-none` 变成圆角、`font-black` 变为较轻字重，会使开发者难以从 JSX 理解最终效果。

建议分阶段迁移到明确组件变体与语义 token。优先移除造成问题的 display/布局覆盖，再逐步清理命名，不宜一次全站替换所有 class。

### 5.3 信息架构与注意力

首页需要情绪与品牌，课程需要持续阅读，词库需要快速查找，复习需要低干扰作答。当前多个页面复用相近的“页面介绍 + 大场景 + 工作台提示 + 实际内容”，使不同任务有近似的进入成本。

“下一集”浮条有助于跨模块推进，但在移动端持续占据底部空间。应按上下文处理：正在答题、输入、录音时减少抢占注意力；保留完成后的明确下一步。此次未实际测试软键盘弹出与安全区变化，不将其写成已确认遮挡故障。

照片上的小字号低透明文字、次级提示和错误色需要进行正式对比度测量。本次只做视觉抽查，不给出未经测量的对比度合规结论。

## 6. 学习逻辑与教学质量

### 6.1 课程覆盖是真实的，但不等于经过等级认证

60 节课共有 512 道练习：200 道 choice、55 道 type、62 道 listen、84 道 cloze、72 道 dictation、39 道 translate。所有 39 道 translate 都配置了备选答案，这是值得保留的内容细节。

项目明确说明没有正式 CEFR 定级，自编听读也没有冒充原生节目，这两点准确。长期路线中 5000+ 词汇等属于目标，不应混进当前可用资源指标。

课程质量需要三个不同层次的检查：结构正确、语言正确、教学顺序合理。当前 validate 和测试覆盖前者较强，后两者依赖有限抽样。A01 说明结构合法的内容仍能教错。

### 6.2 判分与完成证据

`checkAnswer()` 使用 NFC、空白和尾部标点归一化后，与标准答案和 acceptable 精确比较。这适合拼写、固定填空和受控翻译；对开放表达仍会把未枚举的正确表达判错。不能简单改为忽略所有空格，因为韩语间隔本身可能是学习目标。

输出证据检查使用韩文音节数、词多样性、重复率、源文本重合和改写差异等启发式规则。它可以阻止空文本、复制和明显敷衍，但不能证明语法正确、语用合适或发音准确。录音的存在与时长也不能证明发音质量。

建议把“任务完成”“规则检查”“学习者自评”“教师/人工反馈”分别标识。记录不通过的具体原因；在报告或能力栏中避免将其包装成客观语言水平测量。

### 6.3 SRS 与能力分

SRS 已有短间隔学习阶段、ease、lapse、最长 180 天间隔和近期历史。单纯二值判分容易理解，但无法区分勉强想起和非常熟练。短间隔阶段答错立即到期，成熟卡答错会按原间隔缩短，未必“马上再出现”；文案应准确解释。

能力分基于事件累计和最高贡献去重，是学习活动指标，而不是经过标定的掌握概率。建议在 UI 解释其计算依据。不要只凭柱状条判断听说能力，也不要在没有真实长期数据时宣称最优记忆算法。

### 6.4 自由学习与门槛

多条入口允许看内容，但正式进度仍受入门、前置课、词库数量及任务证据约束。这是防止虚假通关的合理产品选择，同时与“自由自学”的直觉存在张力。

建议在入口就区分“自由浏览”和“计入正式进度”，向有基础用户提供明确的水平确认路径作为后续产品议题。此次不将“没有分级测试”当成既有功能缺陷。

## 7. 数据、安全与部署

### 7.1 数据持久化

localStorage 保存学习记录，IndexedDB 保存录音，没有账号和服务端同步。用户清理站点数据或换浏览器后无法自动恢复属于现有产品边界，README 与设置已有说明。

当前多数提交尝试协调多个 key，并在失败后回滚。这比静默写入可靠，但 localStorage 多 key 加 IndexedDB 仍不是统一事务。部分回滚失败被忽略；并发标签写入缺少统一版本和事务协调。这是架构风险，不能据此直接宣称已经发生大规模丢失。

后续宜统一提交结果、事务日志/版本和恢复提示；录音及强关联证据可考虑放入同一 IndexedDB 事务范围。先完成 A02/A03，再评估迁移成本。

### 7.2 安全边界

已设置 `nosniff`、`DENY`、Referrer-Policy 和限制相机/定位的 Permissions-Policy。未见账号鉴权与跨用户数据端点，因此不能把用户可修改自己的 localStorage 当成越权漏洞。

本次生产依赖扫描为零已知漏洞；这只说明当前扫描结果。CSP、HTTPS、HSTS、服务端访问日志与真实站点响应头需要结合部署环境评估，不宜仅因仓库未配置就定为严重漏洞。内联主题脚本会影响未来 CSP 策略设计。

### 7.3 资产与交付成本

图片同时保留 PNG 源文件和 WebP 展示文件，追溯性较好；但源文件放在 public，会进入可部署资产范围。Next Image 在配置与组件内均 `unoptimized`，`sizes` 因此不会自动带来真正的多尺寸图片选择。

建议评估静态生成多尺寸 WebP/AVIF 或启用受控图片优化；将不需要在线回退的源文件移到非 public 位置前，先调整 VisualPanel 的源图回退契约。不要把整个图片目录总量误认为首屏下载量。

## 9. 审计结论

当前项目已经有值得继续建设的基础：实际内容规模、统一学习模型、细致的错误恢复意识和较完整的测试链路。近期最有价值的工作是修正教学错误、保护用户数据，并让移动端更快进入真正的学习操作。

完成 P1 和关键 P2 后，下一轮审计应重点验证真实学习者能否理解进度门槛、完成听读输出、找回复习记录，以及设备/网络异常后是否能继续学习，而不是只检查页面可以打开和按钮能够点击。
