# Kirina Korean 全面审计 · 2026-09-11

## 结论与范围

审计开始时，项目已经具备完整的本地学习闭环，但测试通过不等于测验有效。本轮确认 12 项问题：1 项发布阻断、4 项学习结果可信度问题，以及 7 项内容、导航与工程质量问题。

**最终状态（2026-09-12）：12 项均已修复并验收。** 全仓 strict、410 项测试、生产构建、117 条 HTTP 路由与完整浏览器回归通过；全量依赖审计为零已知漏洞。下文保留修复前证据，最终验收见文末与修复计划。

审计对象是当前工作区（基线提交 `bcc2ce9`，包含此前尚未提交的前端重设计），不是仅审查 Git 差异。覆盖 `src`、`tests`、`scripts`、配置、内容生成链和设计/发布文档：全仓静态扫描、内容结构全量校验、核心状态链逐段审查、关键语言项目人工核对、自动测试及浏览器验收。第三方依赖通过公告和锁文件核查；未逐行审查 node_modules、音频二进制或所有词条的母语自然度。没有真实学习者实验，不将测试分数等同于实际语言水平。

基线证据保存在 `.browser-check/audit2-*.log`：内容验证通过，398 项现有测试通过；全量 `--strict` 暴露 25 处类型错误；生产依赖审计报告 3 个受影响包（1 critical、1 high、1 moderate）。最终验证结果见文末及配套修复计划。

审计启动于 9 月 11 日，修复与验收跨日继续到 9 月 12 日。文件清单按路径、行数、大小和 SHA-256 记录在 `.browser-check/audit2-inventory.json`；内容校验覆盖全部 47 个韩文项目及上述课程/词条/语法/材料，而语言自然度判断采用重点核对，不冒充全量教师审校。

交付版 [源码与配置清单](audit-source-inventory-2026-09-12.json) 共 214 个文件：141 个源码文件、19 个脚本、32 个测试文件、10 份设计文档、1 个 CI 配置，以及 11 个根目录配置/说明文件。此清单说明扫描对象，不表示每行都经过同等深度的人工审查。

## 现有基础

- 内容规模：60 课、722 词、83 语法点、5 组韩文字母、29 份听读材料。课程共 512 道题：选择 200、输入 55、听选 62、填空 84、听写 72、翻译 39。
- 路线由字母与收音、基础句子、交际功能、连贯表达，逐步进入语域与语用。模块前置条件全量检查未发现材料数量门槛死锁；材料进入进阶门槛前已有足够可达材料。
- `workspace.ts` 统一写入；快照读取、进度规范化、SRS、草稿、录音和备份分层。已有存储失败回滚、过期 SRS 快照防护、备份结构检查，以及课程断点恢复时重新判题。
- 前端已收敛为“今日 / 学习 / 练习”，韩文文字碎片形成视觉识别。本轮保留这个方向，解决导航回退、恢复状态和实际操作密度，不再任意增加首页功能。
- 本地存储无需账号，但设备之间不会自动同步，清理浏览器会丢失数据。现有备份说明明确录音不随文本备份导出；这是产品边界，不能宣传成云同步或离线 PWA。

## 问题清单

### A01 · P0 · 生产依赖包含已公告严重漏洞

证据：`package.json` 固定 Next 16.2.12、sharp override 0.35.0；锁文件包含 baseline-browser-mapping 2.10.34。JSON 审计包含 Next Windows RCE 和 AVIF 图像优化 RCE。当前运行环境是 Windows，App Router 未开启 Cache Components，命中前者部署条件。没有执行利用验证，也没有证据表明已经遭受攻击。

图像优化已经 `unoptimized: true`，降低了 AVIF 路径暴露，但不能修复 Windows 漏洞。升级 Next/eslint-config-next 至公告修复版本 16.3.3、sharp 至 0.35.4、baseline-browser-mapping 至 2.11.0，并重新构建与审计。不要用提高 audit 阈值掩盖问题。

补充检查开发依赖后，还发现 brace-expansion、browserslist、js-yaml、postcss-selector-parser 的拒绝服务公告。它们由构建/lint 工具链引入；本轮也按兼容版本范围更新，不把开发工具风险误称为线上已遭入侵。

依据：[Next Windows 公告](https://github.com/advisories/GHSA-p293-qw3h-jr36)、[Next AVIF 公告](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4)、[sharp 公告](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)、[baseline 公告](https://github.com/advisories/GHSA-w5vr-8v7q-w6rv)。

### A02 · P1 · 非听力题答题前泄露答案音频

证据：`drill-runner.tsx` 对任何非听写且有 `speak` 的题提供“听”；`quiz.ts` 与 `gate.ts` 为汉译韩、词汇选择和填空设置答案/完整例句音频。全量课程扫描中，21 课存在包含填空答案的 `speak`。

影响：任务从主动提取变成照音转写，测出的不是提示声称的能力。答题前只允许听力任务或已完整显示的阅读文本播放；翻译、输入、填空的答案音频在反馈后开放。保留听力题必要音频和反馈纠音。

### A03 · P1 · 音频排队成功被当作播放证据

证据：`drill-runner.tsx` 的 5 秒超时把 `playQuestionAudio()` 的接收返回值当作 `started`；自动播放被阻止的 `needs-gesture` 状态没有覆盖所有输入/快捷键提交路径。

影响：没有实际收到播放开始事件，也可能产生有效听力答案。修复为实际 `onstart` 事件才开放答题；超时进入可恢复失败，按钮与键盘共享提交守卫。设备无声可跳过，但不能记成听力掌握。

### A04 · P1 · 发音测验包含不可可靠听辨项目

证据：`hangul.js` 已说明 `ae-e` 常近同音、`oe-we` 可同音，但 `buildPronunciationGate()` 仍强制做两道孤立音节听辨。一般发音对比的随机选项还可能漏掉对比项。韩文门槛使用完整例词问“哪个字母”，例如 우유 同时包含两个目标元音，题干未指定位置。

修复：近同音项目改为有语义/构字条件的拼写辨析，并将其能力证据归入读写；真正发音对比必须同时展示对比项；字母听辨明确初声、元音或收音位置，排除常见合流音作为唯一音频线索的干扰项。ㅚ/ㅟ 说明区分规范单元音与允许的双元音读法，避免把书写组合分类等同于语音分类。

### A05 · P1 · 开放输出被精确匹配判错，旧草稿又可能判对

证据：`quiz.ts` 要求“复述一个核心信息”，实际与归档字符串精确比较；输出题 `acceptable` 同时包含目标改写和原草稿。

影响：正确的同义复述被判错，未修正的旧表达反而得到间隔复习奖励。保持自由写作在有明确标准的自评流程中；自动评分题明确为回忆归档目标句，仅接受目标文本及明确等价答案，不声称理解语义或自动判断自然度。

### A06 · P2 · 课程评估边界接受重复或不完整答题

证据：`lesson-assessment.ts` 过滤未知 ID 后保留重复题，分项分母是已提交答案数，未检查全题覆盖；总分来自调用者。正常 UI 顺序答题与恢复校验减小了暴露，但领域 API 不应依赖组件永远正确。

修复：已知题去重并检查覆盖率；未完整提交不得达成核心掌握；总分不能高于从当前有效答案算出的分数。保留无音频降级、已有进度恢复和失败回滚语义。以缺题、重复题、虚高总分、正常完整答题验证。

### A07 · P2 · 音变说明缺少适用范围

证据：`sound-changes.js` 将“收音 + ㅇ”一概写成连音，将所有 ㄴ+ㄹ 写成流音化，将任何 ㄷ/ㅌ+이 写成腭化。

影响：学习者把教学简式推广到不适用的词或语素边界。补充助词/词尾/后缀条件、实词边界和流音化例外；保留正确高频例子，避免凭口诀生成新音频。

依据：[韩国国立国语院《标准发音法》](https://www.korean.go.kr/kornorms/m/m_regltn.do?regltn_code=0002) 第 4、12–15、17、20 条；[国立国语院关于复合元音与双元音的答复](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=&pageIndex=1&qna_seq=315691)。网页部分直开返回 403，核对采用同一官方页面的搜索索引及官方答复，不把口语合流描述成规范取消区别。

### A08 · P2 · 干扰项与正确答案不在同一语义层级

证据：多处语法题的正确答案是例句译文，干扰项却取 `grammarPoints.meaning` 的规则描述。词库中 联系 同时对应 명사 연락 和 동사 연락하다，反向提问未标词性。语用复习也未优先使用内容作者提供的专门干扰项。

修复：译句选项统一来自句子译文，句型解释题才使用规则描述；歧义词义题补充词性或上下文；语用题沿用经过区分的干扰项。验证各生成器和多个随机种子，不能只修一个页面。

### A09 · P2 · 学习流程跳回旧的独立功能页

证据：`studioHref()` 已有映射，但 TaskCard、LibraryGateNotice、课程结果、复习/错题页仍直接使用 Next Link 指向旧路径。

影响：用户从简洁的整合界面进入旧页，导航结构和选中状态不连贯。统一内部链接映射，保留素材 ID、查询参数、hash 和兼容旧地址；集中处理，避免每个组件重复判断。

实际手机截图还显示练习空状态有重复错题入口、嵌套面板和全零统计。移除整合页重复入口，空状态只保留一个主要操作，统计仅在已有卡片时显示；手机隐藏这一空状态里单独占行的装饰，避免把操作推到屏幕外。

听读标签和表达筛选还直接展示 `listening`、`foundation`、`expressions` 等内部分类名，已替换为“听辨发音”“基础交际”“个表达”等中文说明；筛选 ID 与历史数据保持兼容。

### A10 · P2 · 全量 TS 严格检查未开启

证据：`tsconfig.json` 的 `strict:false`；额外启用严格模式产生 25 处错误，涉及课程 `.find()` 结果、session 可空状态、证据字段、动态索引和语音设置类型。

修复：按领域类型、类型谓词和空状态守卫修正，开启全量 strict。既有 JS 内容边界检查继续保留；不以 `any`、非空断言或关闭检查压制错误。

### A11 · P2 · 缺少产品内的错误与未找到恢复页面

证据：`src/app` 没有 `error.tsx` / `not-found.tsx`。默认框架 404 与中文产品断裂，运行时错误缺少返回学习或重试路径。

修复：提供简洁中文恢复页、可访问的标题、重试和返回入口，404 保持正确状态码，不把失败伪装成空数据。

故障注入发现：`/study?view=listening` 的动态代码块加载失败后，客户端跳转到同一路径的 `/study` 会保留错误边界。错误页的重试/返回使用完整页面加载以丢弃失败的动态模块状态；这是有浏览器回归覆盖的导航例外，普通学习链接仍使用客户端导航。

### A12 · P3 · 发布说明与实际视觉不一致

证据：README 顶部仍展示季节场景及“三幕学习”旧设计，当前实现已是文字贴纸、学习便笺和整合工作区。

修复：以最终浏览器截图更新 README，关联当前设计文档、审计及计划；历史稿留作档案。交付必须实际查看桌面和手机渲染，不能仅凭构建成功称视觉验收完成。

## 学习路线与内容质量判断

1. 顺序合理不等于难度已经实证标定。当前路径可以保留：先建立文字/声音映射，再词句、情境、篇章与语用。60 课中早期字母练习密度高，支持按需补基础，比为追求“少页面”删除能力前置更合理。
2. 需要区分识别、听辨、主动产出、语义理解。修复 A02–A08 是为了让题型、评分和能力证据一致。复习分数是站内任务结果，不是 TOPIK、CEFR 或口语流利度认证。
3. 检索练习研究支持在反馈前先尝试回忆，但不能直接证明本项目的 80% 门槛、每个复习间隔或课程有效性。[Roediger & Karpicke, 2006 原始研究](https://doi.org/10.1111/j.1467-9280.2006.01693.x)。保持纠错反馈与间隔复习，先解决泄题和假证据。
4. 词条和语法的 ID、引用、例句、题目结构采用全量机器验证；语义自然度、礼貌程度、音频韵律仍需要母语教师抽检和真实用户任务观察。没有这部分证据时，不承诺“母语级”或自动批改开放作文。

## 工程与极简性原则

统一领域写入和导航，避免为了少页面而把所有逻辑塞进一个组件；保留可独立测试的纯函数。小型本地应用不需要引入后端、全局状态框架或复杂服务层来证明“工程化”。当前优先强化边界契约、错误恢复、依赖可更新性和回归证据。

视觉验收以首页、学习、练习、字母、听读、表达、设置和错误页为代表，检查手机与桌面的内容宽度、溢出、标题层级、可操作控件与真实导航。保留现有文字贴纸素材和不对称排布；学习任务本身优先于装饰。
