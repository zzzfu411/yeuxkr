## 5. 现在的维护边界

- `progress-normalization.ts`：已存数据的归一化与证据验证。
- `workspace-snapshot.ts`：学习状态、能力、任务推荐的只读计算。
- `workspace.ts`：学习写入、回滚与兼容的公共领域接口。
- `use-learning-workspace.ts`：统一 Provider、存储订阅和 React 接口。
- `lesson-result-actions.tsx` / `lesson-evidence-panels.tsx`：练习结果和录音证据的独立生命周期。
- `curriculum.js`：完整课程供服务端和内容工具使用；`curriculum-runtime.js` 与生成目录服务共享学习逻辑。
- `backup-schema.ts`、`site-metadata.ts`、`library-pagination.tsx`：备份输入、页面元数据、分页的统一实现。

修改课程后执行 `npm run content:prepare`，再运行检查；不要手工编辑运行目录。旧页面仍有显式 `any`，领域中的部分 JS 内容来源也保留渐进兼容，不能将本次 strict 范围描述为整个项目已消除弱类型。

## 6. 发布步骤

1. 在部署环境或 `.env` 中将 `NEXT_PUBLIC_SITE_URL` 配置为真实 HTTPS 根地址。
2. 运行 `npm run check:release`，再运行 `npm run check:all` 与 `npm run audit:prod`。站点地址改变后必须重新构建。
3. CI 使用保留的示例域名验证 canonical、OG 和 sitemap 分支；正式部署使用自己的地址。远程工作流需要在提交后实际运行，本轮验证在本机完成。
4. 在目标设备完成入门试听、录音与下载、导入取消/确认、学习恢复等验收，再面向真实学习者发布。

运行命令与数据说明见 [README](../README.md)。部署地址未设置时，本地版本省略绝对 canonical、OG 图片与 sitemap 条目。

## 7. 持续演进项

这些事项需要真实设备、专业判断或后续产品决策，保留明确范围：

- **教学审校：** 韩语专家全量审核释义、用例、语用与难度；自动检查只能覆盖结构、引用和可机械验证的一致性。
- **设备与学习体验：** iOS Safari、Android 和低端设备的真实录音、系统语音、后台切换及输入法测试；收集实际学习者反馈。
- **本地数据：** 文字备份不含录音；换设备、换域名或清理浏览器前分别导出。localStorage 不具备数据库级跨标签原子事务，整库导入/重置应在单页完成。
- **代码维护：** 历史页面继续减少显式 `any`，按实际修改频率细分长组件；保持核心领域 strict 和内容契约通过。
- **运营能力：** 账号、云同步、跨设备恢复、服务端监控属于后续产品扩展，本轮保持本地优先架构。
