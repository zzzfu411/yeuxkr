# Kirina Korean · 四季片场视觉规范

Kirina Korean 是一个中文母语者使用的韩语学习应用。新版把学习组织成一部安静的生活成长剧：每次打开网站像进入新一集，季节和光线提示阶段，清楚的字幕式排版负责把人带到下一步。

一句话：**把每天的韩语学习，拍成一段有季节、有留白、也有下一集的生活。**

完整调研、现状审计与实施记录见 `design/kdrama-redesign.md`。本文件是后续开发必须遵守的当前视觉契约。

## 1. 核心原则

- **先讲清下一步。** 首页首屏只解释“现在学什么、为什么、从哪里开始”，不堆仪表盘。
- **季节承担情绪。** 春日、雨季、晚秋和蓝夜改变光线与色温，不改变信息架构。
- **场景胜过装饰。** 用雨窗、空座、站台、街灯、杯子和书桌传达氛围；不靠爱心、韩剧字体或人物剧照。
- **留白带来节奏。** 大画面、开放段落、短标题和紧凑列表交替出现，不把所有内容塞进同款卡片。
- **功能始终优先。** 韩文笔画、输入、答题反馈、焦点状态和数据状态必须清楚；氛围不能遮盖学习证据。

明确停用旧的纸本语言：不再新增纸纹背景、胶带、毛边、印章、毛笔标题、手写英文、持续全页 grain 或近乎无圆角的纸卡。历史类名只作为迁移兼容层，不代表允许恢复旧样式。

## 2. 色彩与主题

默认色不是奶油配陶土，而是春雨后的瓷白、蓝灰和少量山茶粉。

| 角色 | token | 默认值 | 用法 |
|---|---|---:|---|
| 页面 | `--paper` / `--canvas` | `#f4f6f5` | 大面积背景 |
| 正文 | `--ink` | `#172235` | 正文、标题、主要图标 |
| 深景 | `--night` | `#152136` | 画面字幕层、蓝夜主题 |
| 雨幕 | `--mist` | `#a8b8c8` | 次级表面与图像调色 |
| 山茶 | `--camellia` / `--seal` | `#ba5665` | 当前状态、主要强调、错误 |
| 新叶 | `--leaf` | `#567c64` | 完成、成功、可继续 |

四个主题共享布局与组件层级：

- `yuan`：`봄 · 春日`，瓷白、雾蓝、山茶粉。
- `yue`：`여름 · 雨季`，浅水绿、天空蓝、珊瑚粉。
- `qing`：`가을 · 晚秋`，冷灰米、苔绿、莓果红。
- `ye`：`겨울 · 蓝夜`，午夜蓝、月光灰、柔粉高光。

状态色从主题 token 推导，禁止在页面组件里新增不随主题变化的大面积硬编码色。深色主题不能退化成纯黑、高对比控制台。

## 3. 字体、圆角与深度

- H1/H2、韩文大字和片头标题：`Noto Serif KR Variable`，中文回退到 Songti SC / SimSun。
- 正文、导航和控件：PingFang SC、Microsoft YaHei、Apple SD Gothic Neo 与系统 sans。
- 英文与数字使用正常句式大小写；避免装饰性全大写和夸张字距。
- 大场景圆角使用 `--hero-radius`（约 28px），图像框使用 `--screen-radius`（约 22px），内容面使用 `--radius`（约 16px），控件使用 `--radius-sm`（约 12px）。
- 普通内容面依靠底色、留白和极淡边线分层；阴影只留给首屏画面、浮动“下一集”和弹出菜单。
- film grain 只能很弱地叠在图片内，不能覆盖正文或随页面滚动闪烁。

## 4. 原创图像语言

所有生成资产采用自然主义的韩国生活剧照感：季节自然光、真实日常质感、克制景深、低饱和蓝绿、少量山茶粉和轻微 35mm 颗粒。

可以出现：雨窗、空站台、公交窗、两把椅子、社区咖啡馆、空白笔记本、耳机、玻璃杯、花枝和远景城市灯。

不能出现：在世演员或可辨认人物、复制剧照、片名标志、可读伪文字、水印、假 UI、奢华商业棚拍、霓虹赛博、过度磨皮、爱心拼贴或宝丽来模板。

核心场景在 `src/data/visuals/assets.ts` 登记，来源与 prompt 在 `src/data/visuals/manifest.ts` 留档。每项页面资产必须同时保留 PNG 源图和 WebP 展示图，并经过尺寸、压缩和引用校验。

## 5. 壳层与信息架构

- 一级导航只放：今日、路线、韩文、复习、听读。
- 自学、错题、测验、词汇、语法、自然表达和设置进入“全部场景”。URL 与功能不变。
- 桌面不使用常驻左栏；下一项以右下角窄浮条呈现，移动端变成安全区上方的底条。
- 品牌标记是代码绘制的四格季节窗，不使用生成式文字 Logo。
- 顶部栏保持半透明和轻量；导航可以在窄屏内部滚动，绝不能撑宽页面。

## 6. 页面构成

- **首页：** 一幅宽银幕场景、一个下一步操作、“今天的三幕”、当前季与自由入口。统计退到页面末尾。
- **模块页：** PageHeader 负责页面身份；ModuleHero 用“文案 + 场景”建立情绪；功能内容再进入开放段落与少量表面。
- **课程与测验：** 题目、输入、语音与证据优先，不用氛围图分散注意力。
- **复习与错题：** 反馈短、准确、可恢复；错误以山茶色提示，不使用惩罚性大红块。
- **听读：** 场景图、逐句文本和播放控件共处；播放器是学习工具，不主导全站结构。
- **空状态与完成态：** 使用对应原创场景并给出明确下一步，不只显示装饰图。

## 7. 交互与可访问性

- 悬停最多轻移 2px 或改变边线/亮度，不旋转、不弹跳。
- `prefers-reduced-motion` 下取消非必要动画。
- 点击目标至少 44px；键盘焦点使用清晰的 2px 主题轮廓。
- 图片必须有准确 alt 或明确标为 decorative；资源失败时显示可读降级文本。
- 1440×1000、1024×768、390×844 和 320px 宽度不得出现横向溢出、遮挡或不可达菜单。

## 8. 实施边界

视觉重构不得改变课程数据、路径推荐、SRS、测验引擎、录音、语音、workspace model 或本地持久化契约。组件仍优先复用 `PageHeader`、`ModuleHero`、`Surface`、`VisualPanel`、`Button` 与统一 token；新页面不得自建另一套视觉系统。

验收需要同时通过 `validate`、TypeScript、ESLint、341 项单测、生产构建和浏览器 smoke，并人工检查桌面与移动截图。
